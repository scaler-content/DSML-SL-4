Mission 1

A faster way to measure impurity

Entropy works well, but computing log2 for every candidate split, at every node, on a large dataset adds up. Gini impurity measures the same idea, the impurity of a node, without needing a logarithm at all.

Gini = 1 − Σi pi2

For a binary outcome with proportion p for one class:

Gini = 1 − p2 − (1 − p)2

Like entropy, Gini is 0 for a pure node and highest for an even 50-50 mix, just on a slightly different scale: its maximum is 0.5, not 1.

Entropy and Gini side by side

Drag the slider to change the class proportion.

Both curves peak at p = 0.5 and touch zero at the two ends. They rarely disagree on which split is best in practice, which is why DecisionTreeClassifier uses Gini as its default criterion, purely for speed.

Node impurity calculator

Enter class counts for a node.

def entropy(p):
    if p == 0 or p == 1:
        return 0.0
    return -p * np.log2(p) - (1 - p) * np.log2(1 - p)

def gini(p):
    return 1 - p**2 - (1 - p)**2

p_values = np.linspace(0.001, 0.999, 200)

plt.plot(p_values, [entropy(p) for p in p_values], label='Entropy')
plt.plot(p_values, [gini(p) for p in p_values], label='Gini impurity')
plt.xlabel('P(class = 1)')
plt.ylabel('Impurity')
plt.title('Entropy vs Gini impurity')
plt.axvline(0.5, linestyle='--', color='gray')
plt.legend()
plt.show()
Mission 2

Splitting on numerical features

Our attrition data has both categorical features (already one-hot encoded for us) and numerical ones, like Age and MonthlyIncome. For a categorical feature, a tree splits on distinct categories. For a numerical feature, it needs a threshold.

How is the threshold chosen?

1. Sort

Sort the feature’s values in increasing order.

2. Try each candidate

Use each value as a candidate threshold, splitting the data into “less than” and “greater than or equal to”.

3. Score each split

Calculate the information gain for each candidate split.

4. Keep the best

Pick the threshold that gives the maximum information gain.

If two different features happen to give exactly equal information gain, there is no way to know for certain which is truly better, so the tree simply picks one at random.

# A small toy example: Age vs Attrition, to see threshold search directly
toy_age = np.array([22, 23, 24, 25, 27, 30, 33, 36, 40, 44, 48, 52])
toy_attrition = np.array([1, 1, 1, 0, 1, 0, 0, 0, 1, 0, 0, 0])

parent_entropy = entropy(toy_attrition.mean())

# Candidate thresholds: midpoints between consecutive sorted ages
candidates = (toy_age[:-1] + toy_age[1:]) / 2

gains = []
for t in candidates:
    left = toy_attrition[toy_age < t]
    right = toy_attrition[toy_age >= t]
    weighted = (len(left)/len(toy_attrition)) * entropy(left.mean()) + \
               (len(right)/len(toy_attrition)) * entropy(right.mean())
    gains.append(parent_entropy - weighted)

best_threshold = candidates[np.argmax(gains)]
What to notice

Every single candidate threshold needed its own entropy calculation. Now imagine a feature with 1,000 distinct values, at every node, for every feature, while building the whole tree. This gets expensive fast.

A cheaper alternative: binning

Instead of testing every unique value, group the feature into ranges first. For example, instead of testing every possible Age value, we could bin ages into groups: [20, 30), [30, 40), [40, 50), [50, 60]. The tree then only has a handful of boundaries to test, at the cost of some precision in where exactly the split falls. The widget above lets you see that trade-off: switch to bin edges and compare the best gain you can reach.

Mission 3

Why deeper trees overfit

Recall from Class 3: our first tree scored 1.0 on training data and about 0.76 on test data. That gap is overfitting.

Why does this happen as depth increases?

Imagine 1,000 employees at the root node. Every split divides the data further. By the time we are several levels deep, a leaf might contain only a handful of employees, some of which are just noise or outliers rather than a genuine pattern. The tree ends up drawing a rule around a few odd points instead of a real trend. If every leaf is allowed to become pure, training accuracy hits 100%, but the tree has essentially memorised the training set.

And if the tree is too shallow?

Say we stop growing at depth 2. Many employees who left and many who stayed will still be mixed together in the same leaf, since 2 levels is rarely enough to separate them cleanly. A lot of “stayed” employees might get bucketed with “left” employees, and vice versa. This is underfitting: the tree is too simple to capture the real pattern.

Shallow tree

Fewer splits, so fewer axis-parallel cuts through the data. More bias, less variance.

Very deep tree

Many cuts through the data. Less bias, more variance.

This is the same bias-variance idea from Class 2, now controlled by tree depth instead of k.

Pruning

Stopping a tree from growing all the way to pure leaves is called pruning. It is the standard fix for a tree that overfits.

Tuning the tree properly

DecisionTreeClassifier exposes several hyperparameters that all control, in different ways, how much the tree is allowed to grow. See the scikit-learn documentation for the full list.

These are all ways of stopping the tree before it grows all the way to pure leaves, which is exactly the pruning idea from Mission 3.

Choosing depth with cross-validation, not guesswork

Rather than pick one train/validation split and eyeball it, we use k-fold cross-validation: split the training data into k folds, train on k−1 of them and validate on the remaining one, k times over, then average the results. This gives a more reliable picture of how each depth actually generalises.

10-fold cross-validation

Each row is one round. Choose a round to see which fold is held out.

Train foldsValidation fold
After ten rounds, the ten validation scores are averaged, and so are the ten training scores.
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import KFold, cross_validate

kfold = KFold(n_splits=10, shuffle=True, random_state=7)
depths = [3, 4, 5, 6, 9, 11, 13, 15]

mean_train_acc = []
mean_val_acc = []

for depth in depths:
    tree_clf = DecisionTreeClassifier(random_state=7, max_depth=depth)
    cv_results = cross_validate(tree_clf, X_train, y_train, cv=kfold,
                                 scoring='accuracy', return_train_score=True)
    mean_train_acc.append(cv_results['train_score'].mean())
    mean_val_acc.append(cv_results['test_score'].mean())

best_depth = depths[np.argmax(mean_val_acc)]

Mission 5

What decision trees do and do not need

Does a decision tree need scaled features?

No. A tree only cares about the order of values, since it searches for a threshold like “Age < 35”. Standardising Age changes its scale, but not the order of employees by age, so the chosen threshold and the resulting impurity are unaffected. This is different from kNN, where scale directly changed distances.

You can check this yourself: flip the Age scale switch in the threshold widget in Mission 2. The values change, the sorted order does not, and neither does the gain at any split.

Encoding categorical features

Suppose a Zipcode feature has 10,000 distinct categories. One-hot encoding it would create 10,000 child branches, each with very few employees, which quickly hurts prediction quality. It is the same curse-of-dimensionality problem from Class 2, in a different guise.

Target encoding converts each category to a single numeric value, avoids that dimensionality explosion, and is usually the better choice for high-cardinality categorical features in a tree.

High-dimensional data

With many features, the tree has to check every possible split, on every feature, at every node. More features means more splits to test, which means longer build times. This is a real cost, distinct from the curse of dimensionality we saw affecting distance in kNN.

Imbalanced data

Since a tree tries to minimise impurity (or maximise information gain), it can end up prioritising the majority class: correctly classifying more of the majority class reduces impurity more than getting a few minority-class points right. This is exactly why we balanced the training set with SMOTE before training, back in Class 1’s data preparation habit.

Feature importance

How do we know which features the tree is actually relying on? For each feature, we add up the information gain it contributed, weighted by how many datapoints passed through the nodes where it was used, across the whole tree. This is called normalized information gain, and it is what scikit-learn reports as feature_importances_.

Different libraries can calculate feature importance slightly differently; this is one common approach, not the only one.

How the importance chart is built

importances = tree_clf.feature_importances_

One score per feature: its information gain, weighted by how many datapoints reached the nodes that used it, summed across the tree and normalized.

indices = np.argsort(importances)[::-1]
names = [X_train.columns[i] for i in indices]

argsort gives positions from smallest to largest; reversing it puts the most important feature first, and the names follow the same order.

Mission 6, bonus

Can a tree predict a number?

The Product team wants to know if decision trees can also handle regression, where the target is continuous rather than a category (like a future delivery-time metric).

The trouble with entropy and Gini here

Both entropy and Gini impurity are built around class probabilities. A continuous target has no such thing. So a DecisionTreeRegressor needs two different ingredients:

A different impurity

It uses Mean Squared Error (MSE) instead of entropy or Gini.

A different leaf prediction

It uses the mean of the target values in that leaf, instead of a majority vote.

How does the tree build itself for regression?

The process mirrors classification exactly, with MSE in place of entropy and mean in place of majority vote.

  1. Calculate the MSE at the current node, using the mean of the node’s target values as the prediction.
  2. Try each feature and each candidate threshold, and compute the reduction in MSE each split would give.
  3. Pick the split with the largest MSE reduction. This plays the same role as information gain.
  4. Repeat on each child, until MSE is small enough or a stopping hyperparameter is hit.

The prediction line looks like a staircase, flat within each leaf and jumping at each split threshold. This is a direct, visual consequence of how a tree predicts: every point in the same leaf gets the exact same predicted value, the mean of that leaf.

Wrap up

  1. Gini impurity measures the same thing as entropy but skips the logarithm, which is why it is scikit-learn’s default and usually just as good.
  2. For a numerical feature, a tree searches candidate thresholds and picks the one with the highest information gain; binning trades some precision for much lower search cost.
  3. Deeper trees overfit because leaves end up with very few points, some of which are just noise; shallower trees underfit because classes stay mixed together. Pruning means stopping a tree before it grows all the way to pure leaves.
  4. max_depth, min_samples_split, min_samples_leaf, max_leaf_nodes, max_features and class_weight are the main levers for controlling tree growth, and depth should be chosen using cross-validation, not a single guess.
  5. A tree does not need scaled features, since splits only depend on the order of values, not their magnitude.
  6. High-cardinality categorical features are better target-encoded than one-hot encoded, and very high-dimensional data slows down tree building, since every feature is checked at every split.
  7. Imbalanced data can bias a tree toward the majority class, which is exactly why we balanced our training set with SMOTE.
  8. feature_importances_ is based on normalized information gain, contributed and weighted across every split where a feature was used.
  9. For regression, a decision tree replaces entropy and Gini with MSE, and replaces the majority vote with the mean of a leaf’s target values, producing a staircase-shaped prediction.
